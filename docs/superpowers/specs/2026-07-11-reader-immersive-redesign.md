# 悟典沉浸阅读页优化设计

## 背景与问题

当前阅读页在真实 API 模式下直接把章节列表中的首章摘要作为正文渲染。章节摘要的 `sentences` 固定为空，因此首屏只剩标题、工具栏和翻页按钮，形成大面积无意义留白。即使正文存在，现有连续双栏列表也缺少章节进度、段落节奏和明确的主要操作，整体更像数据表而不是阅读体验。

## 方案比较

1. **轻量修补现有双栏**：修复正文加载并增强分隔和字号。改动最小，但难以根治“工具栏 + 数据列表”的平淡观感。
2. **沉浸式典籍书页（采用）**：正文以纵向阅读流为中心，用段序、原文、可展开译文和逐句精讲建立节奏；章节信息、阅读进度和导航围绕正文组织。兼顾桌面与移动端，最符合“悟典”的经典阅读定位。
3. **固定原文 + 侧栏译解**：研究效率最高，但小屏适配复杂，也会把普通用户的注意力分割成两个工作区。

## 视觉方向

采用“现代典籍编辑页”而非仿古卷轴。底色保持温润宣纸色，主文字使用墨色，朱砂仅用于当前状态和核心操作，青绿色用于阅读进度与完成反馈。背景加入克制的纸张层次和细线，不使用装饰性卡片堆叠。

章节顶部由书名、章节序号、章节标题、当前阅读进度构成紧凑导读区。正文限定在舒适行宽内，每个句段有稳定序号；原文作为视觉主角，译文默认可见但降低层级，AI 精讲作为句段级操作。页面尾部显示本章完成状态，并提供上下章上下文标题。

## 交互与状态

- 首次加载章节列表后，立即请求当前章节详情；切章时显示正文骨架状态，避免渲染空章节。
- 章节目录继续使用抽屉，但入口同时展示当前章序与总章数。
- 字号设置保留四档，按钮使用清晰的字号示例和无障碍标签。
- 夜间模式与影像底本保留，工具栏在桌面端保持吸顶；移动端压缩为两行或横向可滚动的稳定控件区。
- 已读操作显示“标记已读 / 本章已读”两种状态，并在进度中即时反映。
- 空正文、请求失败和加载中均有明确状态，不再出现只有标题的大空白页。

## 实现边界

主要修改 `frontend/app/reader/page.tsx`、`frontend/components/reader/ReadingView.tsx` 和 `frontend/components/reader/ChapterSelector.tsx`，必要时在 `frontend/app/globals.css` 增加阅读页专用样式。保留现有注释、实体卡片、影像底本和 AI 讲解面板的数据接口，不改后端协议。
