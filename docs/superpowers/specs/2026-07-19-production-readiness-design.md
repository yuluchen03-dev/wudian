# 悟典生产上线加固设计

- **日期：** 2026-07-19
- **状态：** 已完成方案确认和规格自检，待用户复核
- **发布形态：** 真实全栈正式服务
- **部署基线：** Linux + Docker，前后端分离，PostgreSQL 生产持久化，SQLite 仅用于本地开发与测试

## 1. 背景与目标

悟典即将正式上线。当前代码可以完成前端生产构建，现有自动化测试也能通过，但这些结果尚不足以证明项目具备生产可用性。审计已确认空生产数据库无法注册、社区操作使用固定身份、辩论会话没有所有权隔离、部分前后端契约不一致、生产配置缺少强制校验、依赖存在已知安全公告，以及运行数据和重复演示资源进入版本库等问题。

本设计的目标是：在保留现有产品定位和主要交互的前提下，把项目收敛为可部署、可迁移、可隔离、可观测、可回滚且能够通过真实业务验收的全栈服务。

域名、DNS、备案和云厂商采购不在本次范围内。静态 Mock 站可以作为单独命名的演示产物保留，但不能成为生产构建的隐式回退路径。

## 2. 审计基线

截至 2026-07-19，已获得以下基线证据：

- 根目录 `npm test` 通过；后端为 34 passed、2 skipped，跳过项与 ChromaDB 集合不可用有关。
- 后端测试覆盖率约 49%，认证、安全、社区和学习服务的关键分支覆盖不足。
- 前端 `next build` 通过并生成 19 个静态页面，但仍有 Webpack 缓存快照警告。
- 前端 lint 命令进入交互式 ESLint 初始化提示并以 0 退出，因此不能视为 lint 通过。
- 全新 SQLite 数据库在生产模式下 `/health` 返回正常，但首次注册因缺少 `users` 表而返回 500。
- 社区接口对写操作使用固定用户 `1001`、固定用户名 `zengzi` 和固定等级 `12`。
- 辩论会话没有 `owner_id`，历史列表和会话操作未按用户隔离，运行时会话被保存为仓库内 JSON。
- 成就、排行、挑战、阅读进度、引用跳转、复习结果和 SSE 错误处理存在已复现的契约或状态问题。
- 默认 JWT 密钥、生产 Debug 默认值、健康接口信息泄露、缺少限流和密码 72 字节静默截断不符合生产要求。
- 前端直接依赖的 Next.js 版本存在 Critical 和 Moderate 级生产安全公告。
- Python 依赖全部使用无上界的 `>=`，没有锁定文件或 Python 版本声明，且实际脚本使用的 Pillow、测试使用的 pytest 未完整声明。
- 生产检查脚本检查 `NEXT_PUBLIC_API_URL`，应用实际读取 `NEXT_PUBLIC_API_BASE`；静态站构建脚本强制启用 Mock。
- 默认测试没有覆盖所有已有资源测试；仓库没有 CI 工作流。
- 仓库包含大量辩论运行时 JSON、日志、重复 Demo ZIP、展开后的重复资源和第三方压缩资源副本。
- 桌面和 390px 移动端主流程可以渲染，未发现横向溢出；部分触控目标不足 44 x 44，首屏入场低透明度持续时间偏长。

这些基线只说明已知问题和已有能力。实施完成后必须重新执行完整验收，不能用本节结果代替最终证据。

## 3. 方案选择

采用“分阶段全栈加固”路线：沿用当前 FastAPI、Next.js 和 SQLAlchemy 体系，先修生产阻断问题，再统一接口与失败状态，随后完成依赖、发布工程、冗余清理和体验优化，最后执行全新环境验收。

未采用以下方案：

- **紧急补丁路线：** 仅修空库和明显页面错误会留下身份冒用、会话越权、配置泄露和依赖漏洞，不能满足正式服务的上线标准。
- **大规模重构路线：** 重写认证、数据层或前端框架会扩大回归面并延迟上线；当前问题可以在既有边界内逐步修复。

## 4. 目标架构

生产环境由前端服务、FastAPI 服务、PostgreSQL 数据库和可选 AI/向量检索依赖组成。前端只调用真实 API；后端是身份、权限和业务状态的唯一可信来源；数据库保存用户、学习、社区、挑战和辩论数据；AI 与向量检索属于可降级依赖。

```text
Browser
  -> Next.js frontend
      -> typed API client
          -> FastAPI authentication and authorization
              -> application services and transactions
                  -> PostgreSQL
                  -> optional LLM / vector store
```

生产容器入口先执行数据库迁移，再启动 API。存活探针只判断进程是否存活；就绪探针检查配置、数据库连接和迁移版本。LLM 或向量库不可用时，相关能力返回明确的可恢复状态，但基础阅读、学习记录和社区功能继续服务。

SQLite 保留给本地开发和自动化测试。实现需保持 SQLAlchemy 模型与查询在 SQLite 和 PostgreSQL 上均可运行，但生产文档与 Compose 默认使用 PostgreSQL。

## 5. 数据库与迁移

### 5.1 Alembic 版本链

建立可从空数据库执行的 Alembic 初始迁移，并为后续模型变更生成增量迁移。生产环境禁止依赖 `create_all()` 隐式建表。容器启动脚本执行 `alembic upgrade head`，失败时退出，不启动半可用 API。

就绪检查必须验证当前数据库 revision 已达到代码要求。`/health` 不得返回环境名、模型名、绝对数据库路径、向量库路径或会话目录。

### 5.2 数据归属

- 社区加入、签到、笔记、点赞、评论和 PK 操作使用认证上下文中的当前用户，移除所有固定身份字段。
- 辩论会话增加非空 `owner_id` 外键；创建时由当前用户写入，读取、继续、删除和历史查询均按所有者过滤。
- 阅读进度、复习结果、挑战提交、成就和排行积分都以数据库状态为准，前端本地状态只能用于乐观展示，不能作为最终记录。
- 公开内容允许匿名读取；个人记录、社区写操作、辩论历史和 AI 消耗型操作要求登录。

### 5.3 一致性与幂等

用户注册、积分变化、签到、挑战提交和其他跨表写入使用事务。数据库通过唯一约束防止同一用户同日重复签到、重复加入同一小组、重复点赞同一资源及同一次挑战重复计分。

需要重试的写请求携带稳定幂等标识。若相同标识已成功处理，后端返回同一业务结果；若正在处理或载荷冲突，返回明确的冲突响应。

### 5.4 现有运行数据

仓库内辩论会话 JSON 不导入生产数据库，因为这些文件缺少可靠用户归属，导入会造成隐私和所有权歧义。必要的固定辩题以受版本控制的种子数据保存；用户会话只写数据库。运行目录加入 `.gitignore`，已有跟踪文件在确认无静态消费者后从版本控制中移除。

## 6. 认证、授权与安全配置

### 6.1 令牌模型

使用默认有效期 15 分钟的访问令牌和默认有效期 30 天的可撤销刷新令牌；有效期可以通过受校验的生产配置缩短。刷新令牌通过 `HttpOnly`、`Secure` Cookie 传输；前端与 API 位于同一站点时固定使用 `SameSite=Lax`。只有部署拓扑确实跨站时才允许显式改为 `SameSite=None`，并同时保留 `Secure`、来源校验和 CSRF 防护。访问令牌不长期存入 `localStorage`。刷新与登出端点采用 CSRF 防护，所有跨源凭据请求只接受显式允许的生产来源。

刷新令牌在数据库中保存不可逆摘要、过期时间、撤销状态和最小设备元数据。刷新时轮换令牌；复用已轮换令牌时撤销对应会话族。

### 6.2 授权规则

授权在后端资源查询边界实施，而不是依赖前端隐藏按钮。资源存在但不属于当前用户时返回 403；资源不存在返回 404。列表查询从源头按用户过滤，禁止先取全量再在应用层过滤。

社区公开浏览不要求登录，写操作要求登录。辩论会话、学习进度和个人历史只允许所有者访问。需要管理员能力时必须使用明确角色或权限，不使用用户名、固定 ID 或前端字段推断身份。

### 6.3 生产启动校验

当 `APP_ENV=production` 时，以下条件任一不满足都必须启动失败：

- JWT 签名密钥仍为默认值、为空，或 UTF-8 编码后少于 32 字节；
- Debug 开启；
- 数据库地址为空或不是 PostgreSQL 连接；
- CORS 来源为空、包含通配符、包含路径、使用非 HTTPS（明确允许的本地测试环境除外），或包含 localhost/环回地址；
- 令牌、Cookie 和可信代理配置不一致；
- 必需持久化目录不可写。

密码在哈希前按 UTF-8 字节长度验证。超过哈希后端支持限制时返回 422 和稳定错误码，不允许静默截断。登录和注册响应避免泄露账号是否存在的额外信息。

### 6.4 限流和响应头

登录、注册、刷新、AI 生成和其他高成本端点采用按 IP 与账户组合的限流。默认基线为：登录每个 IP/账户组合每分钟 5 次，注册每个 IP 每小时 3 次，刷新每个会话/IP 每分钟 30 次，AI 生成每个用户每分钟 10 次且每小时 30 次；所有阈值可通过受校验的生产配置收紧。达到限额时返回 429、稳定错误码和 `Retry-After`。生产入口统一设置 CSP、HSTS、`X-Content-Type-Options: nosniff`、`Referrer-Policy: strict-origin-when-cross-origin` 和默认拒绝相机、麦克风、地理位置的 Permissions-Policy；静态导出中不会生效的 Next.js headers 不作为唯一保障。

## 7. API 契约与前端数据流

### 7.1 单一契约

后端 Pydantic 响应模型是 API 契约的唯一来源。前端为每个端点定义匹配的 TypeScript 类型，并对生产边界进行运行时校验。字段不匹配必须暴露为可观察错误，不能使用空数组、零值或宽泛类型把错误伪装成成功。

需重点修正并覆盖：

- 成就列表的响应包裹结构；
- 排行百分比和数值转换，禁止出现 `NaN%`；
- 挑战题目的 `verse_id` 与 `chapter_id` 语义；
- 阅读进度的章节映射与后端持久化；
- 引用跳转的 `source`、章节定位和 `highlight`；
- 复习提交结果与成功提示；
- 社区和挑战请求失败后的加载状态；
- PK 倒计时结束、锁题和自动提交。

### 7.2 请求状态

统一 API 客户端负责基地址、认证、超时、请求取消、错误规范化和追踪标识。页面使用明确的 idle、loading、success、empty、error 状态；所有异步路径在 `finally` 中结束 loading。失败时保留可恢复的输入或已取得结果，并提供重试操作。

401 触发一次受控刷新；刷新失败则清理本地会话并进入登录流程。403 不伪装为登录过期；404、409、422、429 和 5xx 分别显示可行动的错误状态。

### 7.3 SSE

SSE 客户端同时处理非 2xx HTTP 响应、服务端业务错误事件、网络中断和用户取消。服务端发送结构化事件类型和稳定错误码。中断时保留已经生成的文本，页面允许从明确状态重新请求；空 catch 块不得吞掉业务错误。

### 7.4 阅读与学习闭环

引用卡片导航到阅读器时传递统一的作品标识、章节标识和高亮文本。阅读器解析参数、加载目标章节、滚动到匹配位置并渲染可见高亮。无法匹配时仍打开正确章节，并提示未定位到原句。

“标记已读”、复习完成和挑战提交只有在后端确认写入后才显示成功。网络失败时保留待提交状态，不增加积分、不更新成就，也不显示完成提示。

## 8. 错误模型与可观测性

后端错误采用统一结构，至少包含稳定 `code`、用户可理解的 `message`、可选字段级 `details` 和请求 `request_id`。日志记录同一请求标识、路由、状态、耗时和安全过滤后的上下文，不记录密码、令牌、Cookie、完整 AI 提示或私人对话内容。

预期业务错误使用 4xx；未处理异常使用统一 500 响应并写入服务端日志。数据库或迁移不可用影响核心就绪状态；LLM、向量检索不可用使用 503 或功能级降级响应，不把整个站点标记为不可用。

前端错误提示面向操作结果，不暴露堆栈、内部路径或模型配置。错误边界覆盖页面级渲染异常，关键表单和流式对话提供局部恢复路径。

## 9. 构建、依赖与部署

### 9.1 构建模式

生产构建只允许真实 API 模式，统一使用应用实际读取的 `NEXT_PUBLIC_API_BASE`。若生产命令检测到 `NEXT_PUBLIC_USE_MOCK=true`，立即失败。

Mock 演示构建使用明确命名的独立命令和输出目录，其产物不得覆盖或冒充生产产物。Windows PowerShell 辅助脚本可以保留用于本地便利，但 CI 和生产流程必须有跨平台 Node、Python 或容器入口。

### 9.2 依赖管理

- 将 Next.js、React 生态和相关配置升级到不存在已知 Critical/High 生产公告的兼容版本，并按官方迁移要求处理行为变化。
- 前端提交锁文件，CI 使用确定性安装命令。
- 声明受支持的 Python 版本；生产与开发依赖分组；补齐 Pillow、pytest 和其他实际引用依赖。
- Python 使用可复现的锁定或约束文件。直接依赖限定在已测试的兼容次版本系列，锁文件固定全部直接与传递依赖的精确版本及哈希；CI 只从锁文件安装。
- 对 `python-jose`/`ecdsa`、Starlette、Pillow 等审计项逐项确认实际依赖路径并升级、替换或记录不可利用的证据。

### 9.3 容器与运维

提供前后端生产 Dockerfile、Compose 参考配置、非 root 用户、只读应用文件系统和明确的数据卷。发布说明包含环境变量清单、迁移、启动、探针、日志、数据库备份、恢复演练和回滚步骤。

数据库迁移和应用发布需要兼容滚动顺序。破坏性 schema 变更采用扩展、迁移、收缩步骤，不在一次发布中先删除旧字段。

## 10. 冗余清理

清理遵循“先证明没有消费者，再删除，再构建验证”的顺序。候选项包括：

- 辩论会话和其他运行时 JSON；
- `backend/init_log.txt` 等运行日志；
- 已有展开副本的 Demo ZIP 或与当前演示产物重复的目录；
- 未被源码、构建脚本或报名材料引用的 Three.js 压缩副本；
- 不再参与发布的旧演示资源；
- 经源码与报名材料脚本搜索确认无用途的根依赖，如 `pptxgenjs`。

若某项仍被报名材料、离线演示或发布脚本引用，则将其归入明确的归档/演示边界，而不是直接删除。第三方资源保留时必须同时保留许可证信息。

`.gitignore` 覆盖运行会话、日志、数据库、构建输出、缓存和本地环境文件，但可提交的环境变量示例文件使用显式例外规则保留。

## 11. 体验与可访问性

核心导航、轮播和工具按钮在移动端达到至少 44 x 44 CSS 像素的触控目标，并提供清晰焦点样式和可访问名称。首屏主内容不能在较长入场动画期间保持低可见度；尊重 `prefers-reduced-motion`。

固定格式控件使用稳定尺寸，加载、错误、长文本和动态数值不能造成明显布局跳动或文本溢出。桌面与移动端验证登录、阅读、引用跳转、挑战、社区和辩论主流程，检查横向溢出、遮挡、键盘导航和错误恢复。

## 12. 测试策略

所有行为修复遵循测试驱动：先写能够复现问题的失败测试，确认失败原因正确，再实现最小完整修复，最后运行相关测试与全套回归。

### 12.1 后端

重点覆盖：

- 从空数据库执行 Alembic 后可注册、登录和刷新；
- 生产配置错误时启动失败；
- 密码字节长度边界；
- 登录、注册和 AI 限流；
- 社区写操作使用当前用户并隔离不同账户；
- 辩论所有者能够访问，其他用户收到 403 或过滤后的列表；
- 签到、点赞、挑战提交和积分写入的幂等性与事务回滚；
- 健康与就绪响应不泄露内部配置；
- LLM 与向量库不可用时的降级语义。

认证、安全、社区、辩论和学习服务的语句覆盖率与分支覆盖率均不得低于 80%；全局覆盖率不得低于实施前 49% 的基线。覆盖率只作为缺口信号，不能代替业务断言和跨用户测试。

### 12.2 前端

重点覆盖：

- API 响应的运行时校验和错误映射；
- 成就、排行、挑战、阅读进度和复习契约；
- 401 刷新、403、422、429 和 5xx 页面状态；
- SSE 业务错误、网络中断和取消；
- 引用跳转、章节定位和高亮；
- loading 在成功与失败路径均能结束；
- PK 倒计时归零后的锁定与单次提交；
- 移动端触控目标、焦点标签和减少动画模式。

### 12.3 发布门禁

CI 统一执行：

1. 前端全部脚本测试，包括当前默认命令遗漏的运行时资源测试；
2. TypeScript 类型检查和非交互 ESLint；
3. 前端生产构建；
4. 后端全部 pytest 与覆盖率报告；
5. 全新 PostgreSQL 的迁移及注册登录烟测；
6. 前后端生产依赖安全审计；
7. Docker 镜像构建与健康检查；
8. 桌面和移动端关键流程浏览器测试。

## 13. 分阶段实施与回滚

实施顺序如下：

1. 建立迁移、生产配置校验、健康/就绪边界和可复现依赖；
2. 修复社区身份与辩论所有权，增加事务和幂等约束；
3. 统一 API 契约、认证刷新、错误模型和前端失败状态；
4. 修复阅读、复习、挑战、成就、排行和 PK 的业务闭环；
5. 完成容器、CI、安全依赖升级和运维文档；
6. 清理已证明无消费者的运行数据与重复资源；
7. 完成可访问性、性能和真实浏览器回归；
8. 在全新生产等价环境执行最终门禁。

每阶段保持可独立验证。数据库变更优先向后兼容；前后端契约变更在同一发布窗口内支持过渡版本。若某阶段失败，回滚应用镜像；涉及数据迁移时使用已验证备份恢复或向前修复迁移，不执行未经演练的破坏性降级。

## 14. 上线验收标准

只有同时满足以下条件，项目才可判定为具备上线条件：

- 全新 PostgreSQL 实例可从零迁移并完成注册、登录、刷新和退出；
- 阅读、引用跳转、进度、复习、挑战、成就和排行形成真实持久化闭环；
- 社区不存在固定身份，跨用户写入与查看权限测试通过；
- 辩论会话按所有者隔离，仓库不再保存用户运行会话；
- 生产默认密钥、Debug、宽泛 CORS 和错误数据库配置会阻止启动；
- 健康接口不泄露内部路径或模型配置，核心与可降级依赖状态可区分；
- 登录、注册和 AI 接口限流有效，密码不会被静默截断；
- 前端没有永久 loading、失败伪成功、`NaN%`、错误章节或丢失 SSE 错误；
- lint、类型检查、全部测试、生产构建、容器烟测和浏览器回归通过；
- 生产依赖审计不存在未处置的 Critical/High 漏洞；
- 冗余项均有引用证据、删除记录或保留理由，第三方许可证完整；
- 发布文档能够让新环境完成部署、迁移、备份、恢复和回滚；
- 所有未解决项都记录风险等级、处理责任角色、目标日期和上线后处理计划，且不存在阻断级遗留问题。

## 15. 非目标与约束

- 不处理域名、DNS、备案或云资源采购。
- 不重写现有前端设计体系、FastAPI 框架或主要产品信息架构。
- 不把 Mock 数据当作生产失败时的自动回退。
- 不导入无法证明用户归属的历史辩论 JSON。
- 不删除仍有明确构建、报名材料或许可证用途的资源。
- 不以“现有测试通过”替代空库、权限、生产配置和真实浏览器验收。
