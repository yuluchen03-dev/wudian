# 悟典初赛 Demo 3D 重设计规格

## 1. 目标

本次改造面向 TRAE AI 创造力大赛“学习工作”赛道初赛，目标是提高晋级复赛的概率。交付物是一份可通过 ZIP 上传社区、无需联网即可运行的交互式 HTML Demo。

初赛页面首先服务评委，其次服务社区体验者与投票者，最后向潜在企业试点方提供商业证据。页面必须在 10 秒内建立差异，在 90 秒内完成核心体验，并在体验结束后证明可信链路和商业闭环。

## 2. 产品定位

### 2.1 第一目标用户

第一目标用户是 22–35 岁、正在面对职场认可、职业去留、协作冲突与内耗问题的年轻职场人。

### 2.2 第一付费方

第一付费方是企业 HR、学习发展部门和青年人才项目。高校通识课程与就业指导项目作为第二试点场景，不与第一商业路径并列宣传。

### 2.3 核心信念

> 不是让 AI 替你回答，而是让有出处的中国思想帮助你判断。

悟典不替用户做决定。它将现实困境拆成可比较的价值冲突，用可核验经典证据组织多种思想立场，再由用户调整价值权重并形成自己的行动判断。

## 3. 差异化原则

页面不使用“AI 助手”“智能学习平台”等同质化定位。AI 只在底层承担知识库检索、引用校验、观点组织和工作流编排，不作为标题或功能名称。

核心差异来自四个方面：

1. 身份明确：年轻职场人，而非泛传统文化用户。
2. 体验明确：进入一场数字思想会审，而非打开聊天窗口。
3. 世界观明确：所有人物、证据、关系和交互都属于同一个未来东方剧场。
4. 闭环明确：现实困境进入，经过举证与交锋，最终形成用户负责的行动判牒。

## 4. 核心功能

核心功能压缩为三个可被评委复述的能力：

1. 将模糊困境拆成可比较的价值冲突。
2. 用原文、出处、白话解释和适用边界组织三种思想立场。
3. 由用户调整价值权重，实时改变行动建议优先级并生成思想判牒。

初赛稳定数据包含三个案件：

- 我很努力，却总不被领导认可，怎么办？
- 稳定但不喜欢的工作，要不要离开？
- 同事抢了我的功劳，我该争还是忍？

## 5. 页面流程

页面使用单一、受保护的状态机：

`选案 → 开审 → 举证 → 交锋 → 调权 → 落判 → 可信与试点终章`

### 5.1 选案

首屏直接显示三个具体职场案件，不先展示功能、技术、市场或团队信息。评委选择案件后即可开审。

### 5.2 开审

问题化为案卷落入 3D 舞台中央。界面显示本案的三项价值冲突，并请三位先贤入席。

### 5.3 举证

立体典籍从空间进入证据区。用户点击或拖动证据，将原文、出处、解释与适用边界加入案卷。证据选择只改变本案重点，不修改原文或人物归属。

### 5.4 交锋

孔子、孟子、老子三位数字人围绕中央案卷发言。支持、反驳和重构使用不同线型与文字标签表达。当前发言者前移、转向并抬手，其他人物退入景深。

### 5.5 调权

用户调整“坚持自我、改善关系、主动改变”三项价值权重。权重改变人物距离、舞台灯光和行动建议排序，不修改经典证据。

### 5.6 落判

舞台收光，镜头推入骨白判牒。朱砂印章落下，显示核心矛盾、共识、分歧、行动建议与保留问题。

### 5.7 可信与试点终章

完成首案后才展示可信链路与企业试点方案，避免营销信息干扰核心体验。

## 6. 可信链路

终章展示正式产品的数据链路：

`问题拆解 → 知识库检索 → 引用校验 → 多思想编排 → 用户调权 → 行动判牒`

每条证据包含原文、出处、人物归属、白话解释和适用边界。检索不到可靠材料时不硬编，不把模型生成内容冒充经典原话。

离线初赛 HTML 明确标注“初赛稳定体验 · 本地策展数据”，不提供伪造的自由提问、模型等待或实时生成效果。

## 7. 商业终章

第一试点是 30–100 人、持续 4 周的企业青年员工成长主题项目。

企业可以查看：

- 参与人数。
- 会审完成率。
- 主题分布。
- 引用展开率。
- 再次开案率。

企业不能查看：

- 个人原始提问。
- 追问内容。
- 个人价值权重。
- 个人思想判牒。

页面只保留一个商业动作：“申请企业青年员工试点”。不同时展示个人订阅、课程采购、出版社合作和融资入口。

## 8. 视觉世界观

视觉方向为“新东方未来主义 × 数字思想剧场”。

- 深墨黑：3D 舞台与空间背景。
- 骨白：原文、证据和判牒。
- 朱砂红：开审、冲突、关键选择与落印。
- 玉青绿：可信引用、关系线与校验状态。
- 金石灰：边界、结构与历史质感。

标题与经典原文使用中文宋体，现代说明和操作使用无衬线字体。页面不使用仿古卷轴、紫色科技渐变、装饰光球、常规卡片仪表盘或持续无意义粒子。

## 9. 实时 3D 方案

使用随 ZIP 本地提供的 Three.js 构建全屏、无装饰边框的 3D 舞台。

三位先贤使用程序化低多边形半身像，不依赖外部 GLB 模型。人物通过轮廓、冠饰、服饰色、名牌和高清肖像建立辨识度。动作限定为呼吸、转头、前移、抬手与退入景深。

3D 调度只服务状态表达：

- 开审：镜头穿过数字殿门，案卷落入中央。
- 举证：典籍飞入证据区，选中证据沿玉青轨迹进入案卷。
- 交锋：当前数字人前移并转向案卷，观点关系连接三席。
- 调权：人物距离与光照响应用户权重。
- 落判：舞台转暗，镜头推进判牒并触发朱砂落印。

高清先贤肖像用于人物详情与移动端降级模式。不使用视频，避免 ZIP 过大、自动播放和移动兼容风险。

## 10. 页面层级

页面分为两层：

- Three.js 舞台层：数字人、案卷、典籍、空间连线、镜头与灯光。
- DOM 信息层：案件、原文、出处、边界、按钮、滑块、可信说明与商业终章。

3D 舞台全屏呈现，不放在装饰卡片或预览容器中。DOM 层保持固定阅读区域和稳定操作区，流式或长文本不得改变舞台尺寸。

## 11. 移动端与降级

移动端不等比缩小桌面三角舞台。一次只突出一位数字人，顶部提供孔子、孟子、老子切换，证据从底部抽屉展开，主操作固定在安全区上方。

降级规则：

- WebGL 不可用：切换高清肖像舞台。
- 初始化超时或帧率持续过低：移除阴影、粒子、景深和反射，仍不足时切换 2.5D。
- 用户开启减少动态：停用镜头推进、震波、视差和印章缩放。
- 单张肖像失败：显示人物名牌和程序化 3D 轮廓。
- JavaScript 失败：保留案件列表、产品定位与安全边界。

## 12. 离线文件结构

```text
悟典-思想审判场-初赛Demo/
├─ index.html
├─ css/
│  └─ app.css
├─ js/
│  ├─ three.module.min.js
│  ├─ court-data.js
│  ├─ court-scene.js
│  └─ app.js
└─ assets/
   ├─ confucius.png
   ├─ mencius.png
   └─ laozi.png
```

`index.html` 是唯一入口。运行时不依赖 CDN、远程字体、在线图片、后端接口或登录状态。ZIP 总体积必须小于社区 20 MB 限制。

## 13. 可访问性与安全

- 所有图标按钮具有可读名称和焦点样式。
- 拖动证据同时提供点击与键盘等价路径。
- 关系类型同时使用线型、文字与颜色。
- 触控目标不小于 44px。
- 经典原文和判牒正文满足可读对比度。
- 悟典提供思想启发，不替代心理、医疗、法律、投资或职业决策。
- 高风险问题不进入普通会审，正式产品应引导用户寻求现实支持。

## 14. 验收标准

- 在 1440px 桌面端与 390px 移动端完整走通七个状态。
- Three.js Canvas 像素非空白，三位数字人可见且构图正确。
- 三位人物动作、立体典籍、观点连线、权重排序与落判反馈可操作。
- 断网后仍可完整运行，无外部网络请求。
- 无水平溢出、文字遮挡、按钮遮挡、布局跳动或空白主场景。
- 完整动态、减少动态和 2.5D 降级均可完成主流程。
- 保存不少于三张关键步骤截图，供初赛帖子展示 TRAE 实践过程。

## 15. 成功标准

评委能够在体验后复述三句话：

1. 这不是一个传统文化 AI 助手，而是一场由用户参与的中国思想会审。
2. 每个观点都有原文、出处和适用边界，用户调整权重但不能改写证据。
3. 产品面向年轻职场人，并可作为保护个人隐私的企业青年员工成长试点。
