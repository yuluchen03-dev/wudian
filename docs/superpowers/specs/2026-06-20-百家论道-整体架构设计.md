# 百家论道 - 整体架构设计

## 一、项目概述

基于现有的"悟典"平台，实现"百家论道"多智能体辩论系统。该系统允许用户抛出一个现代人生困惑，孔子（儒）、老子（道）、墨子（墨）、韩非子（法）四位祖师爷基于各自经典发表立场、互相辩驳，用户可随时打断、追问，最后生成"百家会诊报告"。

## 二、核心功能模块

### 2.1 多智能体编排系统
- **主持Agent（Moderator）**：控场、定发言顺序、防跑题、防死循环、生成会诊报告
- **圣贤Agent**：孔子、老子、墨子、韩非子，每个Agent独立人格画像 + 独立经典语料库
- **踢馆名人Agent**：李白、王阳明等，动态插入辩论

### 2.2 辩论回合逻辑
1. **Round 1（各陈己见）**：主持Agent依次唤起四个圣贤Agent，每个仅基于自己的经典RAG作答
2. **Round 2（交锋）**：把前一轮其他Agent的发言作为上下文喂给当前Agent，指令其针对性反驳
3. **Round 3（响应论主）**：用户介入后，主持Agent路由到被点名/最相关的圣贤
4. **会诊**：主持Agent汇总全场发言，抽取共识/分歧/各自建议，生成报告

### 2.3 引用校验系统
- 每位发言必过原文校验，引用只能来自本派经典
- 引用校验复用现有的RAG检索机制
- 杜绝编造与跨派串台

### 2.4 前端圆桌论道界面
- 圆桌布局：四位圣贤围坐，论主居中下方
- 交锋可视化：Agent反驳谁，就在两者间拉一条朱红连线+箭头
- 引用展示：原文用朱砂色+虚线下划，点击滑出原文卡
- 流式输出：四子依次流式输出（打字机效果）

## 三、技术架构

### 3.1 后端架构
```
┌─────────────────┐
│   主持 Agent     │  控场:定发言顺序、防跑题、
│  (Moderator)    │  防死循环、生成会诊报告
└────────┬────────┘
    ┌──────────┬─────┴─────┬──────────┐
┌───▼───┐  ┌───▼───┐  ┌───▼───┐  ┌───▼───┐
│孔子Agent│  │老子Agent│  │墨子Agent│  │韩非Agent│
│论语 RAG │  │道德经RAG│  │墨子 RAG │  │韩非子RAG│
└────────┘  └────────┘  └────────┘  └────────┘
```

### 3.2 数据模型扩展
- **圣贤人格画像表**：核心价值、说理方式、立场边界、语气样例、经典
- **经典语料库表**：每派系一套经典语料
- **辩论记录表**：辩论会话、发言记录、引用记录
- **踢馆名人表**：人物、时代、语料库、是否解锁

### 3.3 API设计
- `POST /api/debate/start` - 开始辩论
- `POST /api/debate/{id}/respond` - 用户响应
- `POST /api/debate/{id}/summon` - 召唤踢馆名人
- `GET /api/debate/{id}/report` - 获取会诊报告
- `POST /api/debate/{id}/join` - 论主入席

## 六、技术风险与应对

### 6.1 延迟处理
- 多Agent必然多次LLM调用，用流式+轮流呈现把延迟转化为论辩节奏
- 现场用预热议题确保稳定

### 6.2 防失控
- 主持Agent设回合上限与跑题检测
- 辩论保持庄重、不沦为互骂（在prompt中约束"论道而非攻讦"）

### 6.3 人格不串台
- 每个Agent严格绑定自己的经典语料+人格画像
- 韩非不会说儒家话，引用也只能来自《韩非子》
