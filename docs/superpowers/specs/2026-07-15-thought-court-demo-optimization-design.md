# 悟典“思想审判场”Demo 优化设计

## 1. 目标与定位

本次改造将 `/demo` 从面向主持人的“黑客松现场指挥台”改为可直接操作的“思想审判场”。

悟典的首要用户是 22-35 岁、正在处理职场认可、职业选择、协作冲突或内耗问题的年轻职场人。体验的核心不是向一个泛化 AI 索取答案，而是将具体困惑置入可追溯的中国思想会审中：用户选择证据、介入观点权重，并得到共识、分歧、适用边界与可执行的下一步。

产品的商业落点是企业青年员工成长与文化学习试点，而非泛用问答工具。

## 2. 范围

### 包含

- `/demo` 的四幕思想审判场主流程。
- 三个精选职场案件和自由提问入口。
- 可核验的经典证据、三席思想交锋与可调权的思想判牒。
- 基于 CSS 3D 透视、现有素材和 Framer Motion 的舞台调度。
- 真实请求失败后的原地恢复与明确标记的稳定演示层。
- 自动测试与桌面、移动端的浏览器验收。

### 不包含

- 重做首页、阅读器、问道页或圆桌页。
- 新增付费、企业后台、长期个人画像或新的后端契约。
- 引入 Three.js、完整 3D 引擎、AI 数字人视频或重型外部资产。
- 将稳定演示数据伪装为实时模型输出。

## 3. 用户体验

### 第一幕：问·问题落案

首屏直接展示三个精选职场案件：

1. 我很努力，却总不被领导认可，怎么办？
2. 稳定但不喜欢的工作，要不要离开？
3. 同事抢了我的功劳，我该争还是忍？

用户选择案件或输入自由问题后，点击“击鼓开审”。案卷落入舞台中央，界面以可验证的阶段说明处理进度：理解案情、检索典籍、校验证据、请贤入席。精选首案将问题拆为外界认可、自我价值、行动选择三个冲突。

### 第二幕：证·经典举证

右侧证据卷展示原文、出处、白话解释、适用边界与核验状态。用户可点击或拖入案卷，表达本案重点；拖拽只影响证据排序和后续强调，不修改原文、出处或人物归属。每一个拖拽操作均提供“加入本案”的键盘等价路径。

### 第三幕：辩·百家交锋

默认请孔子、孟子、老子入席。三席使用现有 SSE 会话能力或稳定演示数据流式展示观点；用户可以追问、请求互问及选择更认同的立场。观点关系以支持、反驳、重构三种线型表达，并在内容到达后逐步建立，不能仅依赖颜色传达关系。

### 第四幕：判·思想判牒

判牒收束为核心矛盾、三家观点、引用、今日行动和保留问题。用户调节“坚持自我、改善关系、主动改变”三项价值权重后，系统只对既有、可验证内容进行重排和强调。点击“落判”完成收束，用户可重新调权或新开一案。

## 4. 视觉与动效

视觉方向为“数字思想剧场”：深墨舞台、骨白证据与判牒、朱砂关键状态、玉青可信关系、金石灰次级结构。正文与经典原文保持高可读性；不使用仿古卷轴页面、紫色渐变、装饰光球或卡片仪表盘。

舞台采用轻量 2.5D/3D 表达：

- 三位先贤以环绕案卷的稳定立体席位出现；当前发言者前推并聚焦，其他席位退入景深。
- 开审时案卷自上方落案，舞台产生一次短促空间震波。
- 证据以具厚度的典籍碎片进入案卷，选中后形成可见关系轨迹。
- 交锋时观点关系连接席位，随经过核验的内容渐进建立。
- 落判时镜头由深墨舞台推进至骨白判牒，朱砂印章下落收束。

动效通过 CSS `perspective`、`transform-style: preserve-3d`、分层现有图像和 Framer Motion 完成。`prefers-reduced-motion`、移动端或性能不足时，停用景深、震波与长镜头，退化为短淡入和明确的位置切换，始终保留主内容与操作。

## 5. 前端边界与数据流

- `ThoughtCourtShell`：负责四幕有限状态、模式、动态与声音状态。
- `CaseIntake`：负责案件选择、自由输入和开审事件。
- `EvidenceDock`：负责证据查看、核验标记、排序与键盘等价操作。
- `SageTribunal`：负责三席状态、流式发言、追问、互问、立场选择和观点关系。
- `VerdictScroll`：负责显示可追溯判牒、价值权重和落判操作。
- `StableDemoProvider`：提供经过人工校验的精选案件数据，并明确标记 `stable-demo`。

顶层状态固定为 `idle -> intake -> retrieving -> evidence -> debate -> weighting -> verdict -> completed`。并行状态包含 `mode`（`curated | live | stable-demo`）、`motion`（`full | reduced | degraded`）、`network`（`idle | loading | streaming | failed`）与 `citationStatus`（`verified | partial | unavailable`）。组件不通过无约束布尔值组合出未定义状态。

精选案件读取稳定数据。自由问题复用既有辩论与检索 API。远程阶段失败时保留当前问题、舞台与已获得内容，提供原地重试或用户主动切换至稳定层。稳定层始终有可见标识，不得冒充实时模型输出。

## 6. 安全与可访问性

悟典只提供思想启发，不提供心理、医疗、法律、投资或职业决策结论。引用不足时明确说明依据不完整，禁止以舞台权威感掩盖不确定性。高风险问题中止普通会审并提示寻求专业或紧急支持。

所有图标按钮具有可读名称。拖拽操作有点击和键盘等价路径。证据核验、观点关系和四幕进度同时以文本或图形表达。未知长度的流式内容只在固定阅读容器内滚动，不能推动舞台或底部操作区。

## 7. 验收

- 打开 `/demo` 后十秒内可选择案件并开审；精选首案可在九十秒内完成四幕。
- 在 1440px 桌面端与 390px 移动端，主舞台非空、文字与控件不重叠、无水平溢出、触控目标不小于 44px。
- 测试状态机的允许和拒绝转移、精选与自由模式、证据核验、权重排序不改写引用、流式与单席失败、重试及稳定层标识。
- 测试键盘等价操作、减少动态和性能降级。
- 浏览器验证开审、举证、交锋、落判四个阶段，以及真实请求失败后的恢复路径。

## 8. 成功标准

评委与用户进入的不是泛化“AI 助手”页面，而是在明确的职场身份和场景下，以可追溯证据参与一场具有空间记忆点的思想会审。AI 在体验中承担检索、组织与协作职责，而不是作为标题或单独卖点出现。
